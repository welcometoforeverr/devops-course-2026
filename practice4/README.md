# Практическая работа 4 — Python и Go через gRPC с mTLS

Проверяемая среда: Ubuntu 24.04, Python 3.12, Go 1.24.0, nginx из репозитория Ubuntu.

## Подготовка

```bash
sudo apt update
sudo apt install -y nginx golang-cfssl protobuf-compiler python3-venv
# Установите Go 1.24.0 из https://go.dev/dl/, если в системе нет Go >= 1.22.
cd practice4
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
bash verify.sh
```

`verify.sh` создаёт CA и сертификаты, генерирует Python/Go-код, собирает сервер,
проверяет Django/nginx, запускает три web-клиента и выполняет интеграционные тесты.
В конце останавливает только запущенные им процессы. Сертификаты и приватные ключи
не входят в Git; при каждом запуске создаются локально заново.

## Запуск вручную

После генерации сертификатов и кода выполните в отдельных терминалах из `practice4`:

```bash
./dice-server
nginx -p "$PWD/" -c nginx.conf
python manage.py runserver 127.0.0.1:8000
python manage.py runserver 127.0.0.1:8001
python manage.py runserver 127.0.0.1:8002
```

Откройте http://127.0.0.1:8000/ и нажмите «Бросить кубики».
Дополнительные клиенты доступны на 8001 и 8002. Django принимает порт позиционным
аргументом, а не через `-p`. В каждом Python-терминале активируйте `.venv`.

Схема: Django → mTLS :8443 → Go; Django → mTLS :9448 → nginx → h2c :50051 → Go.
Незашифрованный участок ограничен loopback. Это локальный учебный стенд.
`/grpc` и `/nginx` возвращают отдельное значение 1–6; два кубика независимы.

## Проверки

- 20 прямых RPC и 20 RPC через nginx возвращают значения 1–6.
- Без сертификата клиента оба mTLS-входа отклоняют запрос.
- 40 параллельных RPC проходят при 8 рабочих потоках.
- Django GET/POST с CSRF и отдельные маршруты отвечают HTTP 200.
- Три Django-процесса на разных портах успешно используют оба маршрута.
- `go test -race` проверяет потокобезопасность генератора.

## Исправления методички

Согласован порт nginx 9448. Исправлены импорты Python и go_package, пути сертификатов,
маршруты Django, обработка ошибок и таймауты RPC. Шаблон хранится в проекте,
а не внутри установленного Django. Зависимости Go ограничены реально используемыми.
Из генератора случайных чисел устранена гонка при одновременных запросах.
